# Анимации

Каталог скролл-сцен проекта. У каждой есть имя — им можно пользоваться в
разговоре вместо описания: «здесь жалюзи», «этот блок с лентой и уездом».

Имена живут не только здесь: слаг сцены попадает в `data-scene` на секции,
в имя модуля и в имя функции. Если сцена переименовывается — переименовывается
везде, иначе каталог разойдётся с кодом.

## Появление — `intro`

`src/scripts/animations/hero-intro.js` → `initHeroIntro()`

Единственная сцена не по скроллу, а по загрузке. Элементы с `data-hero-intro`
(строки заголовка, подзаголовок, кнопка) по очереди опускаются сверху
и проявляются, порядок — по DOM. Старт ждёт `document.fonts.ready`, но не
дольше короткой паузы, чтобы на медленной сети экран не стоял пустым.

До запуска JS контент прячет модификатор `hero--intro` в `hero.css`, иначе
текст мигает: виден, гаснет, появляется. Это единственное место, где стартовое
состояние живёт и в CSS, и в JS — они совпадают (`opacity: 0`), а JS снимает
модификатор и ставит своё состояние в одном синхронном шаге. Если JS не
загрузился, нулевая CSS-анимация с задержкой `--hero-intro-fallback` всё равно
покажет контент.

## Заливка — `fill`

`src/scripts/animations/heading-fill.js` → `initHeadingFill()`

Заголовок с `data-heading-fill` стоит приглушённым (`--heading-muted`),
и по мере прокрутки слова одно за другим набирают цвет. На слова заголовок
режет скрипт, в разметке он остаётся обычным текстом — как и придёт из ACF.
Первые экраны (`h1` в hero) заливки не получают: у них своё появление.

Где на прокрутке идёт заливка, решает окно открытия — см. `reveal`.

## Черта — `rule`

`src/scripts/animations/rule.js` → `initRules()`

Линия с `data-rule` рисуется от начала к концу, пока выходит на экран, —
окно то же, что у заливки (`reveal`). Линию даёт компонент `.rule`
(`components/rule.css`): псевдоэлемент по верху элемента, для вертикальной
(`.rule--vertical`) — по левому краю; ход задаёт переменная `--rule-progress`,
без скрипта она равна единице. Линии-бордеры под это переведены на компонент:
хозяин линии должен быть позиционирован.

Плюсы с `data-rule-marker` крутятся все разом от положения прокрутки —
`SPIN_PER_SCREEN` градусов за экран, — и стоят, когда стоит страница.
Центровка плюса в CSS задана свойством `translate`, а не `transform`:
поворот GSAP пишет в `transform`, и они не спорят. Крутятся и одиночные плюсы
на фото первых экранов.

## Окно открытия — `reveal`

`src/scripts/animations/reveal.js` → `revealWindow(section, element)`

Механизм для сцен, привязанных к появлению элемента на экране. Возвращает
границы триггера и, в его единицах, с какой точки и какой длины идёт ход:

- **обычный** элемент въезжает снизу — ход от отметки 85% экрана до 45%;
- **подложенный** (секция с `data-underlap`) уже стоит на месте, но закрыт
  предыдущей секцией. Его открывает её уезд (`exitLength`) или, если у секции
  есть жалюзи, их раскрытие (`exitLength × BLINDS_AT + openLength`). Ход идёт
  по второй половине этого открытия и заканчивается вместе с ним — дальше
  секция либо играет свою сцену (атмосфера тут же уводит шапку вверх),
  либо просто едет прокруткой.

Отсчёт у подложенного — от `top top` секции с относительным концом: секция
в это время сама закреплена, и отметку ниже её верха ScrollTrigger сдвинул бы
на длину её пина.

Модули, которые смотрят на `data-underlap`, инициализируются последними:
атрибут ставят сцены секций выше.

## Перекрас — `backdrop`

`src/scripts/animations/hero.js` → `initHeroBackdrop()`

Поверх секции лежит слой цвета следующей секции; по мере её наезда слой
проявляется. Цвет берётся из фактического фона следующей секции, поэтому при
смене её модификатора в админке править ничего не нужно.

**Настройка:** диапазон привязан к наезду следующей секции (`top bottom` →
`top top`), отдельных ручек нет.

**Подводный камень:** слой лежит **поверх** фоновой картинки, потому что та
непрозрачная и слой под ней не был бы виден. Значит вместе с фоном подтушёвывается
и картинка. Когда в hero встанет видео с прозрачным фоном, слой надо будет увести
под него — тогда меняться будет только задник.

## Разъезд — `spread`

`src/scripts/animations/spread.js` → `initSpread()`

Первый экран липкий (`position: sticky`), следующая секция наезжает на него
сверху. Элементы с `data-spread-left` уходят за левый край, с
`data-spread-right` — за правый, а поверх фото проявляется слой
(`data-spread-veil`) цвета следующей секции — тот же приём, что в «Перекрасе».
Закрепления через GSAP нет: липкость даёт CSS, поэтому без JS секция просто
накрывается следующей. Сцена поднимается на каждой секции с `data-spread`.

Разъезд начинается раньше наезда: у первого экрана есть **разбег** — отрезок
прокрутки, на котором он стоит один, а текст уже едет. Следующая секция
показывается снизу, когда текст ушёл на половину, слой проявляется вместе
с её наездом. Разбег — это отступ после секции, скрипт ставит его через
`--spread-lead` (правило в `layout/section.css`), без сцены его нет.

**Настройка:** `SPREAD_SHARE` — ход текста в долях экрана, `LEAD_SHARE` — какая
его часть проходит до появления следующей секции. До какой степени
перекрашивать фото — `--spread-veil-max` на секции (по умолчанию до
непрозрачности).

**Подводные камни:**

1. Секции со скруглённым верхом слой нельзя доводить до непрозрачности.
   В углах фото остаётся видно ещё почти экран прокрутки; закрась его
   полностью — углы сольются с фоном и полукруг пропадёт. Поэтому у «О клинике»
   стоит `--spread-veil-max: 0.6`.
2. Без разбега элементы у нижнего края не разъезжаются, а тонут под наезжающей
   секцией: она накрывает их раньше, чем они успевают сдвинуться. Так было
   с заголовком на странице услуги.

## Растворение — `dissolve`

`src/scripts/animations/about.js` → `initAboutDissolve()`

Секция закрепляется и гаснет целиком, вместе с собственным фоном. Под ней уже
стоит следующая, неподвижно и всю фазу, поэтому подмена основания не читается:
на экране просто остаётся ровный фон.

**Настройка:** длина фазы — `dissolveLength()`, 0.6 экрана. Подкладка — высота
секции плюс длина фазы, по общему правилу (см. «Подкладка»).

**Подводный камень:** секция на время перехода перестаёт быть непрозрачной и
опирается на то, что под ней. Работает, пока под ней тот же цвет.

## Жалюзи — `blinds`

`src/scripts/animations/blinds.js` → `blindsOpen()` — общая формула.
Пользуются ей `pinned-scene.js` (параметр `blinds`), `footer.js`,
`procedures.js` (услуги с выездом) и `reviews.js` (отзывы за уезжающей секцией).

Пять полос цвета предыдущего блока расходятся, открывая содержимое. Полосы
прибиты и к верху, и к низу блока: зазоры появляются только между ними. Отсюда
формула — каждая полоса сжимается по `scaleY` и дополнительно съезжает вниз
на четверть своей высоты, помноженную на её номер.

Разметка и оформление — компонент `.blinds` в `src/styles/components/blinds.css`.
Цвет полос блок объявляет сам через `--blinds-color`: он должен совпадать с фоном
того, что было на экране до него.

**Настройка:** в направлениях длина фазы — `openLength()` из `timing.js`,
в подвале раскрытие
привязано к его собственному появлению в кадре (`top 90%` → `top 40%`): полосы
начинают расходиться, когда подвал уже показался из-за нижнего края, и успевают
разойтись до конца страницы. Подвал не закрепляется: он ниже экрана не занимает,
да и после него страница кончается — прокручивать было бы нечего. По времени
раскрытие совпадает с уездом СТА, поэтому переход идёт без остановки.

Отзывы на страницах услуг подложены под уезжающие «преимущества», и «входа
в кадр» у них нет: секция уже стоит наверху, когда её открывают. Поэтому они
держат себя сами и раскрывают полосы (`reviews.js`): полосы начинают
расходиться, когда предыдущая секция уехала на `BLINDS_AT` (половину)
своего хода, и заканчивают уже после её ухода — переход идёт без остановки.
Предыдущая сцена, увидев у следующей секции жалюзи, удержание не ставит.
Цвет полос там берётся из фона предыдущей секции скриптом.

**Подводные камни:**

1. Полосы показываются только при активной сцене (`[data-scene='on']`).
   Без JS они остались бы закрытыми навсегда и блок не появился бы вовсе.
2. Отзывы без жалюзи (главная) своей сцены не имеют, их держит предыдущая.
   Добавишь им жалюзи в разметке — удержание перейдёт к ним само.

## Стопка — `stack`

`src/scripts/animations/stack-scene.js` → `createStackScene()`

Секция закреплена, карточки лежат в ряд от слота вправо с зазором ряда
(`gap` ленты в CSS): следующая с самого начала выглядывает из-за правого края
экрана. На каждом шаге ряд сдвигается на карточку влево — следующая встаёт
в слот, а та, что его занимала, оседает: уменьшается до 620/700, сдвигается
влево на 340 долей от 700 и уходит под новую. Все осевшие лежат в одном
месте, каждая новая поверх старой: порядок задаёт разметка, z-index не нужны.

Ряд едет равномерно, поэтому у каждой обёртки один линейный твин: из своего
места в ряду в слот за столько шагов, сколько карточек перед ней. Въезд крутит
обёртку карточки (`data-services-item`), оседание — саму карточку
(`data-services-card`). Разные элементы, поэтому два движения по одной оси
не спорят за один `transform` и не нужны фокусы с `immediateRender`.

**Настройка:** шаг — `stackStep()` из `timing.js`, полэкрана на карточку.
Длина фазы — шаг × (карточек − 1). Доли оседания — константы в `stack-scene.js`,
взяты из макета.

**Подводные камни:**

1. Без JS лента прокручивается нативно (`overflow-x: auto`); в режиме сцены
   лента сжимается до слота активной карточки, а карточки встают в него
   абсолютом (`services.css`).
2. Картинкам нельзя `loading="lazy"` — по той же причине, что и в ленте:
   дальние карточки стоят за правым краем экрана.

## Лента — `rail`

`src/scripts/animations/rail-scene.js` → `createRailScene()`

Секция закрепляется, содержимое едет вбок на `ширина ленты − ширина экрана`.
Вместе с лентой можно двигать что-то ещё — например, боковое фото в направлениях
(параметр `travellers`). Что ещё происходит по ходу ленты, секция добавляет
через `build(timeline, at, { length, distance })`: из отношения хода к прокрутке
считается момент, когда точка ленты доедет до нужной отметки экрана.

**Подъём карточек (преимущества).** Карточки, которые в начале показаны
меньше чем на `SETTLE_AT` своей ширины, стоят ниже общей линии на 100 долей
от 754 ширины тела и поднимаются к ней, пока показываются из-за края: подъём
начинается, когда левый край карточки входит в экран, и заканчивается, когда
она показалась на `SETTLE_AT` (0.6) ширины. Видимые с начала карточки стоят
на линии сразу. Опускается тело (`data-advantage-body`), а не карточка: разделитель
слева остаётся на месте. Считается в `advantages.js`.

**Настройка:** ход ленты считается от её реальной ширины на каждом `refresh`,
а прокрутка, которую он стоит, — это ход, умноженный на `RAIL_PACE` из
`timing.js`. Две разные величины: при `RAIL_PACE = 1` семь карточек стоили бы
почти четыре экрана прокрутки, и страница казалась бы вязкой.

**Подводные камни:**

1. Без JS лента прокручивается нативно (`overflow-x: auto`), иначе видна была бы
   только первая карточка.
2. **Картинкам в ленте нельзя `loading="lazy"`.** Карточки стоят сбоку за краем
   экрана, браузер откладывает загрузку и декодирует их прямо посреди сцены —
   в профиле это были кадры по 100–250мс. У всех картинок стоит
   `decoding="async"`, а в лентах `lazy` снят намеренно. При натяжке на тему это
   придётся вернуть руками: WordPress проставляет `lazy` сам.

## Уезд — `slide-out`

`src/scripts/animations/pinned-scene.js`, финальная фаза `createPinnedScene()`

Закреплённая секция уходит влево на `xPercent: -100`, открывая следующую.

**Настройка:** длина фазы — `exitLength()` из `timing.js`.

**Подводные камни:**

1. Длительности фаз задаются **в пикселях прокрутки**, а не долями. Подкладка
   следующей секции считается от длины уезда; если фазы задать пропорцией, уезд
   начнётся не там, где следующая встанет на место, и сверху мелькнёт полоса фона.
2. Секции нужен `z-index` выше следующей, иначе она уедет под неё. Отсюда же
   растёт баг с кликами — см. «Распорка» ниже.

## Раскрытие — `unfold`

`src/scripts/animations/atmosphere.js` → `initAtmosphere()`

Четыре фазы: пауза, пока предыдущая секция уезжает → шапка уходит вверх, медиа
встаёт на её место → превью разрастается в полный кадр → проявляются подписи.

Рост сделан не масштабом: у превью и кадра разные пропорции, и `scale` растянул
бы фото. Вместо этого окно кадра открывается через `clip-path: inset()`, а
картинка внутри масштабируется равномерно.

**Настройка:** `hold()` берётся из того же `exitLength()`, что и уезд
предыдущей секции, — иначе фазы разъедутся. `morph()` — длина раскрытия,
1.1 экрана.

**Подводный камень:** шапка выведена из потока (`position: absolute`) в режиме
сцены. Иначе она держала бы высоту секции, и после раскрытия под кадром
оставалась бы пустота в её высоту.

## Сборка — `gather`

`src/scripts/animations/cta.js` → `initCta()`

Секция закрепляется. Маленький кадр в середине карточки разрастается во всю её
площадь и притемняется, разбросанные по ширине слова заголовка съезжаются
в строку и светлеют на снимке, следом проявляются текст и кнопка. Сборка
заканчивается ровно на снятии с закрепления: дальше собранный блок видно, пока
секция уезжает вверх, а под ней уже расходятся жалюзи подвала.

Рост кадра устроен как в «Раскрытии»: окно открывается через `clip-path`,
картинка внутри масштабируется. Разница в том, что кадрирование в двух
состояниях разное — в маленьком окне виден общий план, в полном кадре нижняя
треть снимка, — поэтому вместе с масштабом едет и `y`.

Разброс слов считается от их собственной раскладки: скрипт замеряет, где слова
стоят собранными, раскладывает те же ширины по ширине карточки с равными
промежутками и берёт разницу как стартовый `x`. Поэтому строка собирается ровно
в ту, что стоит в разметке, и переверстка её не ломает.

**Настройка:** `morph()` — длина сцены, 1.1 экрана. Стартовая геометрия
(окно 642×500 в карточке 1840×880) задана долями в константах модуля.

**Подводные камни:**

1. В CSS описано **финальное** состояние, стартовое поднимает скрипт. Так без JS
   и при отключённых анимациях секция сразу выглядит собранной и читаемой.
2. Обе строки `clip-path` выписаны со всеми четырьмя сторонами. GSAP
   интерполирует строку по числам подряд: запись `inset(0px … )` против
   `inset(top right bottom left … )` даёт разное количество чисел, и на
   промежуточных кадрах радиус уезжает в координату.
3. Слова светлеют позже, чем открывается кадр. Если пустить одновременно, строка
   на несколько кадров оказывается светлой на ещё светлом снимке.
4. Паузы в конце быть не должно. Закреплённая секция без движения читается как
   зависание: экран стоит, а страница прокручивается. Один раз мы этот холд
   поставили и убрали.

## Наслоение — `overlay`

`src/scripts/animations/overlay-scene.js` → `createOverlayScene()` — общий каркас.
Пользуются им двое: `procedures.js` (услуги с выездом) и `steps.js` (этапы).

Секция закреплена. Фото элементов лежат стопкой в одной ячейке, и на каждом
шаге фото следующего открывается снизу поверх текущего (`clip-path: inset()`,
картинка внутри при этом подъезжает снизу на `RISE`). Что ещё меняется на шаге,
секция добавляет сама через `build(timeline, index, at, step)`; текст
подменяется общей парой `hideLayers()` / `crossfade()`: текущий гаснет
с лёгким ходом вверх, следующий проявляется снизу.

- **Услуги:** подменяются описание и название, во вкладках слева зажигается
  следующая, клик по вкладке прокручивает к позиции услуги. Открывается блок
  жалюзи, как подвал: полосы расходятся, пока секция входит в кадр
  (`top 90%` → `top top`), цвет полос скрипт берёт из фона предыдущей секции.
- **Этапы:** подменяется номер в счётчике, список подъезжает вверх до верха
  следующего этапа: пройденный гаснет и уходит за край окна списка,
  следующий набирает цвет. Приглушённость будущих этапов берётся из CSS.

**Настройка:** шаг — `overlayStep()` из `timing.js`, 0.6 экрана на элемент.
Длина сцены — шаг × (элементов − 1). Доли шага на уход и появление текста —
`FADE_OUT` и `FADE_IN_AT` в каркасе.

**Подводные камни:**

1. В разметке спрятаны (`hidden`) все слои, кроме первого: без JS виден один
   элемент, а не шесть текстов друг на друге. Сцена сама снимает `hidden`
   и раздаёт стартовые состояния через `gsap.set()`, CSS про них не знает.
2. Слои гаснут через `autoAlpha`, а не `opacity`: они лежат стопкой в одной
   ячейке, и прозрачный слой поверх активного перехватывал бы курсор у его
   кнопок. Так однажды перестали ховериться кнопки в услугах.
3. Прокрутка к вкладке идёт через `scrollTo()` из `smooth-scroll.js`:
   нативный `window.scrollTo` Lenis перехватывает.
4. Уезда у сцены нет: после последнего элемента секция просто снимается
   с закрепления, следующая идёт обычным потоком.
5. Этапы занимают ровно экран: список длиннее окна, и лишнее срезается снизу.
   Сделай секцию по содержимому — после сцены под последним этапом останется
   пустой хвост в высоту ушедших.

## Карусель — `carousel`

`src/scripts/animations/tasks.js` → `initTasks()`

Вторая сцена не по скроллу, а по времени. Круглые карточки задач медленно
едут влево по кольцу, у центра вырастают, к краям уменьшаются: размер
зависит от текущего расстояния до центра ряда — шаг от центра уменьшает
карточку на шестую часть, дальше двух шагов не уменьшает (600 → 500 → 400).
Ход — на тикере GSAP, только пока секция на экране.

Размер меняется масштабом (`transform`), не шириной, а зазоры при этом
держатся ровно: ряд раскладывается от опорной карточки — ближайшей к центру —
вправо и влево по фактическим ширинам. Опорная стоит на своём месте
в кольце, помноженном на расстояние между центрами её и соседа с той
стороны, куда она наклонена: в момент смены опорной обе формулы дают одно
и то же, и ряд не дёргается.

**Настройка:** `SPEED` — шагов кольца в секунду, `MAX_RANK` и `SHRINK` —
предел и шаг уменьшения.

**Подводные камни:**

1. Если карточек мало и ряд не закрывает экран, набор дописывается копиями
   (`aria-hidden`), иначе на краях был бы виден шов кольца.
2. При отключённых анимациях ряд стоит, размеры — по расстоянию от середины
   разметки (`--task-rank`, считает `task-card.css`). Без скрипта карточки
   равны и ряд листается нативно (`overflow-x: auto`).

## Механизмы

### Темп — `timing.js`

`src/scripts/animations/timing.js`

Длины фаз лежат в одном месте, потому что связаны между собой: пауза
«атмосферы» обязана совпадать с уездом «направлений», а подкладка считается
от той же длины. Разъедутся — на стыке мелькнёт полоса фона.

Этот же файл — ручка темпа всей страницы. Закреплённые сцены съедают больше
половины прокрутки, и если сайт кажется тягучим, крутить надо здесь, а не
в отдельных модулях. Для справки: с `exitLength` в экран, `openLength` в экран
и `RAIL_PACE = 1` главная была 19 565px; с нынешними 0.7 / 0.6 / 0.7 — 15 437px.


### Подкладка — `underlap`

Следующая секция заранее сдвинута вверх отрицательным отступом и стоит под
текущей. Благодаря этому она не «приезжает» после перехода, а открывается уже
стоящей на месте.

Величину объявляет скрипт **предыдущей** секции через свойство `--underlap`,
правило одно на всех — в `src/styles/layout/section.css`. Формула тоже одна:

> **высота предыдущей секции + длина её закреплённой фазы**

- после уезда — экран самой секции плюс `exitLength()`;
- после растворения — высота секции плюс `dissolveLength()`.

Слагаемое с фазой обязательно и от типа перехода не зависит: закрепляя секцию,
GSAP подменяет её распоркой в высоту секции **плюс длину пина**, и всё, что
идёт следом, съезжает вниз на эту длину. Не компенсируешь — следующая секция
встанет ниже на длину фазы и вместо ожидания под текущей поедет снизу вверх
наравне с прокруткой, а в конце фазы её резко прибьёт собственным пином.

В CSS константы нет намеренно: при смене темпа сцены подкладка пересчитается
сама. Спотыкались об это дважды: сначала уезд начинался на 150px раньше, чем
следующая секция вставала на место, потом растворение «о клинике» считало
подкладку без фазы — и направления въезжали снизу с рывком.

### Удержание следующей секции

Пока секция уезжает, следующая должна стоять неподвижно, иначе она всплывает
снизу навстречу. Её закрепляет либо `createRailScene` (параметр `holdNext`),
либо она сама, если у неё есть своя сцена.

Удерживаемая секция обычно ниже экрана, и под ней просвечивает её распорка —
светлая полоса на стыке. Распорка красится в цвет секции (`utils/pin-spacer.js`)
и там, где держит `holdNext`, и там, где секция держит себя (отзывы). Красить
распорки всех пинов подряд нельзя: распорка наследует `z-index` секции
и закрасила бы подложенную под неё следующую.

### Пауза в начале сцены

Секция, подложенная под предыдущую, стоит на месте с самого начала её перехода —
а значит и собственный пин ловит там же, по `top top`. Свою сцену она играть
ещё не должна: предыдущая пока на экране. Поэтому сцена начинается с паузы
в длину фазы предыдущей секции — `hold` у `createRailScene` (направления ждут
`dissolveLength()`) или та же величина внутри собственной сцены (атмосфера ждёт
`exitLength()`).

Забудешь паузу — переходы наложатся: у направлений жалюзи разъезжались
одновременно с растворением «о клинике», под ещё видимой секцией.

**Два пина на одном элементе конфликтуют.** Если у следующей секции появляется
собственная закреплённая сцена — удержание переносится в неё, а вызывающей
стороне передаётся `holdNext: false`. Так сделано на стыке направлений
и атмосферы.

### Распорка GSAP

При закреплении GSAP подменяет секцию распоркой `pin-spacer` и **копирует на неё
`z-index`**. Распорка невидимая, но перехватывает нажатия у секции, подложенной
под неё: так однажды перестали кликаться вкладки отзывов.

Лечится общим правилом в `src/styles/layout/section.css` — распорке
`pointer-events: none`, её содержимому `auto`.

Проверять кликабельность нужно попаданием курсора (`elementFromPoint`), а не
вызовом `element.click()`: второй срабатывает даже сквозь перекрытие и такой
баг не ловит.

Распорка ещё и подменяет соседей: после закрепления `nextElementSibling`
секции — распорка следующей, а не сама секция, и закреплённая секция видит
соседей не своих, а своей распорки. Сцены, которым нужен сосед (подкладка,
цвет жалюзи, слой перекраса), берут его через `nextSection()` /
`previousSection()` из `utils/siblings.js` — они смотрят сквозь распорки.
Спотыкались: отзывы на странице услуги закрепили себя раньше преимуществ,
и подкладка легла на их распорку — секция ждала не под преимуществами,
а на два экрана ниже.

### Пересчёт после смены высоты

Всё, что меняет высоту страницы после загрузки, сдвигает отметки триггеров
ниже себя: закреплённые сцены ловят пин по старым позициям и прыгают на входе
и на выходе. Так было с аккордеоном FAQ на странице услуги: после раскрытия
ответа CTA под ним прыгал на сотню пикселей в начале и в конце закрепления.
Лечится `ScrollTrigger.refresh()` по окончании хода (`components/faq.js`);
то же правило для любой подгрузки контента и ленивых картинок без размеров.

### Без `anticipatePin`

У закреплённых сцен `anticipatePin` не ставится. Параметр включает пин заранее —
на 45 мс, помноженных на скорость прокрутки, — чтобы скрыть задержку нативного
скролла. С Lenis задержки нет: прокрутка и пин считаются в одном тике GSAP,
а упреждение остаётся и читается как рывок — секция за один кадр прыгает
на 80–110px в своё закреплённое место, на каждом стыке, в обе стороны.
Один раз так и было, убрали.

## Как добавить сцену на новую страницу

Лента и стопка с уездом переиспользуются разметкой, без нового JS:

```js
import { createRailScene } from './rail-scene.js';

createRailScene({
  section,                 // закрепляемая секция
  track,                   // то, что едет по горизонтали
  travellers: [aside],     // что ещё едет вместе с лентой (необязательно)
  blinds: bars,            // полосы жалюзи (необязательно)
  hold: dissolveLength,    // пауза перед началом, в длину фазы предыдущей секции
  holdNext: true           // держать ли следующую секцию на время уезда
});

import { createStackScene } from './stack-scene.js';

createStackScene({
  section,
  track,                   // слот, в который встают карточки
  items,                   // обёртки карточек — они въезжают
  cards,                   // сами карточки, по одной на обёртку — они оседают
  blinds, hold, holdNext   // как у ленты
});
```

Обе — обёртки над `createPinnedScene()` из `pinned-scene.js`: он держит пин,
паузу, жалюзи, уезд и подкладку, а свою фазу получает снаружи парой
`phase.length()` / `phase.build(timeline, at)`. Новая сцена с уездом — это
новая пара, а не копия каркаса.

Требования к секции: высота в экран, `overflow: hidden`, `z-index` выше следующей,
и правило «без сцены лента прокручивается нативно».

Все сцены обёрнуты в `gsap.context()` и живут внутри
`matchMedia('(prefers-reduced-motion: no-preference)')`. При выключенных
анимациях ни одна из них не поднимается, подкладок нет, секции идут обычным
потоком — это проверяется отдельно, флагом `--force-prefers-reduced-motion`.
