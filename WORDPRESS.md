# Натяжка SkinLove на WordPress

Рабочий документ натяжки: решения, архитектура, план по этапам и журнал сессий.
Решения из раздела «Принятые решения» приняты заказчиком — не пересматривать
без его согласия. Где этот файл расходится с разделом «WordPress» в `CLAUDE.md`,
прав этот файл: CLAUDE.md писался под ACF и Contact Form 7, у нас Carbon Fields
и свой обработчик заявок. Остальные правила CLAUDE.md (БЭМ, токены, GSAP,
необязательные поля, повторяемые элементы) действуют.

## Протокол сессии

Натяжка идёт **по этапам, один этап — одна сессия**. Контекст между сессиями
не переносится, поэтому всё, что нужно следующей сессии, живёт в этом файле.

**В начале сессии**
1. Прочитать этот файл целиком, особенно «Прогресс» и последнюю запись «Журнала».
2. Взять первый незакрытый этап. Не начинать следующий, пока текущий не закрыт.
3. Если в «Открытых вопросах» есть вопрос, блокирующий этап, — сначала задать его.

**По ходу**
- Не держать в контексте лишнего: HTML страниц большой, читать его кусками
  по секции (`awk '/data-section="X"/,/<\/section>/'`), а не целиком.
- Решение, принятое с пользователем по ходу, сразу записывать в «Принятые решения».

**Когда остановиться и передать работу новой сессии**
- этап закрыт;
- контекст был автоматически сжат (в разговоре появилось резюме прошлой части);
- разговор стал длинным: прочитано много больших файлов, десятки правок;
- задача ушла в долгую отладку, не относящуюся к этапу.

**Перед остановкой**
1. Отметить сделанное в «Прогрессе» (`[x]`, частично — `[~]` с пояснением).
2. Добавить запись в «Журнал»: что сделано, на чём остановились (файл, функция,
   секция), что следующее, что сломано или не проверено.
3. Прогнать `npm run build` и проверку PHP (раздел «Проверка этапа»).
4. Сказать пользователю, что сессию лучше продолжить в новой, и дать фразу для
   старта: «Продолжаем натяжку по WORDPRESS.md».

## Открытые вопросы

- [ ] Какая CRM и как в неё отправлять (API, вебхук, ключи). Отложено
      заказчиком: подключаем позже, отдельной задачей после натяжки. Этапы
      не блокирует — заявки пока только сохраняются в админке.
- [ ] Куда ведёт «Больше отзывов» (Google Maps, Instagram?). В вёрстке `href="#"`,
      в сиде тоже `#`; ссылка — поле секции «Отзывы», поменять в админке.

- [ ] FAQ на face: ответы на первый («Когда будет заметен эффект?») и последний
      («Как понять, какая процедура подойдёт…») вопросы, похоже, перепутаны —
      так в вёрстке и макете. В сиде перенесено как есть; если подтвердится —
      поменять местами в `wp/seed/face.php` и в `face.html`.

## Контент и перевод

Контент заносится на каждом этапе вместе с layout'ами своей страницы — этап
не закрыт, пока страница не заполнена на обоих языках.

- **Как заносится.** Сид-файлы в репозитории: `wp/seed/{страница}.php` (и
  `options.php`, `reviews.php`, `programs.php`, `outcall-services.php`),
  запуск через WP-CLI `wp eval-file`. Сид идемпотентный: повторный запуск
  перезаписывает поля, а не плодит записи (поиск по slug / заголовку).
  Картинки из `public/img` загружаются в медиабиблиотеку один раз, повторно
  берутся по имени файла.
- **Источник RU.** Тексты берутся из html вёрстки дословно, вместе с
  неразрывными пробелами. Заголовки с акцентом переводятся в формат `*…*`.
- **Перевод EN.** Делает Claude прямо в сид-файле, рядом с русским текстом —
  так перевод можно вычитать и поправить в одном месте. Правила:
  - тон спокойный, премиальный, без канцелярита и кальки с русского;
    аудитория — англоязычные жители и гости Дубая;
  - медицинские формулировки не усиливать и не обещать результат сильнее,
    чем в русском тексте;
  - названия аппаратов, препаратов и методик (INDIBA, BBL, Genesis, NAD+,
    Laennec, Майерс → Myers' cocktail) — международные, как пишут производители;
  - цены и валюта (AED) не переводятся, формат «600 / 1000 AED» сохраняется;
  - длина EN-строк заголовков и кнопок — проверить в вёрстке на 375 и 1920;
  - новые устойчивые термины добавлять в глоссарий ниже, чтобы на всех
    страницах переводилось одинаково.
- **alt картинок** — русский, в медиабиблиотеке (решение 4).

## Окружение

Всё из папки `wp/`. Адреса: сайт http://localhost:8101, админка `/wp-admin`
(admin / admin, только локально), phpMyAdmin http://localhost:8102.

```bash
cp .env.example .env                 # один раз, пароли БД — любые
docker compose up -d
docker compose run --rm wpcli wp …   # WP-CLI; при первом запуске:
#   wp core install --url=http://localhost:8101 --title=SkinLove --admin_user=admin \
#     --admin_password=admin --admin_email=… --skip-email --locale=ru_RU
#   wp language core install ru_RU --activate
#   wp rewrite structure '/%postname%/'
#   wp theme activate skinlove
docker compose run --rm wpcli wp eval-file /seed/{файл}.php   # сид
```

Тема: `composer install --no-dev` в папке темы (Carbon Fields в `vendor/`),
`npm run build:theme` в корне (ассеты в `assets/` темы). И `vendor/`, и
`assets/` — результат сборки, в git не идут; на сервер тема выкладывается
после обеих команд. Лог ошибок — `docker compose exec wordpress cat wp-content/debug.log`.

## Архитектура

### Тема и сборка
- Структура темы — как в `../invest-wp/wp-content/themes/fundhouse`: `functions.php`
  только подключает файлы из `inc/`, Carbon Fields ставится Composer'ом
  (`htmlburger/carbon-fields`), без `vendor/` в админке показывается уведомление.
- Префикс функций и констант — `skinlove_`, полей Carbon — `sl_`.
- Vite: отдельный режим сборки под тему. Вход — `src/main.js` (не html), выход —
  `assets/` темы, имена без хешей (`entryFileNames`, `assetFileNames`). Подключение
  в `functions.php` с версией по `filemtime`. Статическая сборка для GitHub Pages
  (`npm run build`) продолжает работать как раньше.
  Сделано: `npm run build:theme` (`vite build --mode theme`), список декоративных
  файлов из `public/` — `themeStatic` в `vite.config.js`, URL в шаблоне —
  `skinlove_asset_url( 'img/alfa.svg' )`.
- У страниц нет редактора блоков и поля контента: классический экран,
  конструктор сразу под заголовком, SEO — в боковой колонке.
- Декоративная графика (логотипы, wordmark, бейдж alfa, svg) и видео, завязанные
  на скролл, — в `assets/` темы. Контентные картинки — в медиабиблиотеку.
- Шаблоны:

| Файл | Что |
|---|---|
| `header.php`, `footer.php` | Общие шапка и подвал (+ меню, модалка, contact-dock) |
| `header-outcall.php`, `footer-outcall.php` | Шапка и подвал лендинга Outcall |
| `page.php` | Все страницы, включая главную: выводит конструктор секций |
| `page-outcall.php` | Template Name «Выездные услуги»: тот же конструктор, свои шапка и подвал |
| `index.php` | Обязательный минимум для WP, своей вёрстки нет |
| `template-parts/sections/{layout}.php` | По файлу на layout, имя = `data-section` |
| `template-parts/cards/*.php` | Повторяемые элементы: карточки, строки прайса, отзывы |

404 и правовые страницы не делаем (решение 13).

### Языки
- Язык определяется по префиксу `/en/` в начале запроса. Префикс снимается
  с `REQUEST_URI` до разбора запроса, дальше WP находит страницу по обычному slug.
- На фронте в EN-режиме фильтруется `home_url`, чтобы все ссылки сайта получали
  `/en/`. В админке и REST не трогается.
- `<html lang>`, `og:locale`, `<link rel="alternate" hreflang>` для обеих версий
  и `x-default` на основной язык.
- Переключатель языка ведёт на ту же страницу в другом языке.
- Хелперы (`inc/lang.php`):
  - `skinlove_lang()` → `'ru' | 'en'`;
  - `skinlove_t( $key )` — строка из словаря `inc/dictionary.php`
    (`[ 'menu_open' => [ 'ru' => 'Меню', 'en' => 'Menu' ], … ]`);
  - `skinlove_field( $name, $post_id = null )` → `carbon_get_post_meta( $id, "sl_{$name}_{$lang}" )`;
  - `skinlove_entry( $entry, $name )` — то же для элемента `complex`;
  - `skinlove_option( $name )` — двуязычная опция, `skinlove_option_raw( $name )` —
    одна на оба языка (телефоны, почта, код карты);
  - `skinlove_lang_url( $lang )` — текущая страница на другом языке (для переключателя).
- После разбора запроса `REQUEST_URI` возвращается с `/en/` — иначе
  `redirect_canonical` уходит в цикл. `<html lang>` — `ru` / `en` (фильтр
  `language_attributes`).
- Пустое значение — пустая строка, вызывающий шаблон элемент не выводит.
  Фолбэков на русский и «текстов из макета» нет (решение 3).
- Строки из JS (сейчас только выбор даты: «Предыдущий месяц», «Время»,
  «Сначала выберите день» и т. п.) передаются из словаря через `data-*`.
  Локаль календаря уже берётся из `<html lang>`.

### Поля в админке
- Пара полей создаётся одним хелпером, например
  `skinlove_pair( 'text', 'title', 'Заголовок' )` → `sl_title_ru` и `sl_title_en`
  с подписями «Заголовок (RU)» / «Заголовок (EN)», ширина 50 % каждое.
  В `complex` имена без префикса `sl_`: `skinlove_sub_pair()` → `title_ru`, `title_en`.
  Четвёртый аргумент — донастройка каждого поля, для заголовков с акцентом
  `'skinlove_heading_help'` (подсказка про звёздочки).
- Конструктор: поле `sl_sections` типа `complex` с `set_layout( 'tabbed-vertical' )`,
  каждая секция — layout через `add_fields( '{layout}', 'Название', … )` и при
  этом отдельная вкладка (решение 6). Подпись вкладки — «Название: заголовок»,
  если у layout'а есть пара `title`.
  Новый layout добавляется записью в `skinlove_section_layouts()` (`inc/sections.php`):
  `'reviews' => [ 'label' => 'Отзывы', 'fields' => fn() => [ … ] ]` + файл
  `template-parts/sections/reviews.php`, который получает элемент в `$args['section']`.
  Секции выводит `skinlove_render_sections()` в `page.php`.
- Отдельный контейнер страницы «SEO»: title ×2, description ×2.
- Заголовки с акцентом — одно поле на язык. Разметка: `*…*` — акцентная строка,
  перенос строки — новая строка. Рендер `skinlove_heading( $text )`: сначала
  `esc_html`, потом разбор. Пример: `Начните *с заботы* о себе` → три
  `span.heading__line`, средний с `heading__line--accent`. Второй аргумент —
  атрибут для каждой строки из шаблона (`'data-hero-intro'` у hero).
- Картинки — `image` (ID вложения), вывод через `wp_get_attachment_image()`
  с классом из вёрстки; alt берётся из медиабиблиотеки. Размеры задаёт обёртка
  (`aspect-ratio`), не файл.
- Модификаторы вёрстки (`section--light / --beige`, варианты `program-request`
  и т. п.) — поле `select` в layout'е.

### Заявки
- Эндпоинт `POST /wp-json/skinlove/v1/lead`.
- Поля: имя, телефон, язык, тип формы (`modal`, `cta`, `program-request`,
  `outcall-hero`, `quiz`), источник: ID и заголовок страницы, секция и элемент
  (название программы, акции, процедуры), для квиза — ответы.
- Источник: у кнопок, открывающих модалку, атрибут `data-lead-item="…"`;
  модалка кладёт его в скрытое поле. У форм в секциях — скрытые поля
  с секцией и страницей.
- Как в `invest-wp/inc/leads.php`: сначала заявка сохраняется в CPT `sl_lead`,
  потом уходит в CRM — если CRM недоступна, лид не теряется. Защита: honeypot
  и лимит по IP. Ключи CRM — константы в `wp-config.php`, не в репозитории.
- На фронте `form.js` вместо имитации успеха отправляет `fetch` и показывает
  успех или ошибку. Маска телефона убирается (решение 12), маска имени остаётся.
