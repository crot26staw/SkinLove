# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## О проекте

Статическая вёрстка на чистом HTML/CSS/JS, собираемая через Vite. Анимации — на GSAP.
**Вёрстка потом натягивается на WordPress**, поэтому разметка пишется сразу с расчётом
на разбивку по PHP-шаблонам и вывод контента из админки — см. раздел «WordPress».

Никаких фреймворков (React, Vue, Svelte), никакого TypeScript, никакого CSS-фреймворка
(Tailwind, Bootstrap). Если кажется, что задачу проще решить фреймворком — всё равно
решай ванилой и спроси, прежде чем добавлять зависимость.

## Стек

- **Vite** — дев-сервер и сборка
- **Vanilla JS** (ES-модули, без транспиляции в ES5)
- **CSS** — нативный, с custom properties и вложенностью (без препроцессоров)
- **GSAP** — все анимации

## Команды

```bash
npm run dev       # дев-сервер, http://localhost:5173
npm run build     # прод-сборка в dist/
npm run preview   # локальный просмотр прод-сборки
```

Перед тем как сказать «готово», прогоняй `npm run build` — сборка должна проходить без ошибок.

## Структура

```
.
├── index.html            # точка входа, здесь же <script type="module" src="/src/main.js">
├── vite.config.js
├── public/               # статика «как есть»: favicon, robots.txt, og-картинки
└── src/
    ├── main.js           # единственная точка входа, импортирует стили и модули
    ├── styles/
    │   ├── main.css      # только @import остальных файлов
    │   ├── base/         # reset.css, variables.css, typography.css
    │   ├── layout/       # сетка, контейнеры, общие правила секций
    │   ├── sections/     # по файлу на секцию Flexible Content
    │   └── components/   # по файлу на компонент
    ├── scripts/
    │   ├── animations/   # GSAP-анимации, по файлу на секцию/эффект
    │   ├── components/   # логика UI: меню, слайдер, аккордеон
    │   └── utils/        # хелперы
    └── assets/           # картинки/шрифты, которые проходят через сборщик
```

**Куда класть файлы:** если на ассет ссылается CSS или JS — в `src/assets/`
(Vite хеширует и оптимизирует). Если нужен предсказуемый путь и файл дёргается
напрямую из HTML или извне — в `public/`.

## Конвенции кода

### HTML
- Семантика: `<header>`, `<main>`, `<section>`, `<nav>`, `<footer>`. `<div>` — только когда
  нет подходящего тега.
- Хуки для JS — через `data-*`-атрибуты, не через классы: `data-menu-toggle`, а не `.js-menu`.
  Классы остаются за стилями.
- Каждая интерактивная сущность доступна с клавиатуры, у иконочных кнопок есть `aria-label`.

### CSS
- БЭМ для именования: `.card`, `.card__title`, `.card--featured`.
- Все цвета, отступы, шрифты, тайминги — через custom properties в `base/variables.css`.
  Хардкод значений в компонентах не допускается.
- Мобильная вёрстка первой, медиазапросы через `min-width`.
- Не поднимай специфичность ради переопределения: никаких `!important` и цепочек
  вроде `.section .card .card__title`. Максимум — два уровня.
- Следи за тем, чтобы отступы секций не отменяли друг друга: правило одно, живёт в одном месте.

### JavaScript
- Только ES-модули, `import`/`export`. Один модуль — одна ответственность.
- Каждый модуль экспортирует функцию инициализации, `main.js` их вызывает.
  Никакого кода, исполняющегося при импорте.
- Перед инициализацией проверяй наличие элемента в DOM — модуль не должен падать
  на странице, где его блока нет.
- `const` по умолчанию, `let` при необходимости, `var` — никогда.
- Никаких `jQuery`, никаких полифилов под старые браузеры.

## GSAP

Все скролл-сцены названы и описаны в `ANIMATIONS.md` в корне — сверяйся с ним
перед тем, как делать новую: скорее всего, нужная уже есть и переиспользуется.

### Регистрация плагинов
Плагины регистрируются один раз в `src/scripts/animations/index.js`, больше нигде:

```js
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';

gsap.registerPlugin(ScrollTrigger);
```

Импорт из `'gsap/ScrollTrigger'` — именно так, не из `'gsap/all'` (иначе в бандл
уедет всё подряд).

### Правила анимаций
- Анимируй `transform` (`x`, `y`, `scale`, `rotation`) и `opacity`. Не анимируй
  `width`, `height`, `top`, `left`, `margin` — это дёргает layout.
- Несколько связанных твинов — всегда таймлайн (`gsap.timeline()`), а не цепочка
  твинов с ручными `delay`.
- Начальное состояние задавай через `gsap.set()` в JS или через CSS — но не в обоих местах,
  иначе будет мигание при загрузке.
- Оборачивай анимации в `gsap.context()` и возвращай функцию очистки — это упрощает
  отключение анимаций при смене страницы или брейкпоинта.
- Адаптивные анимации — через `gsap.matchMedia()`, а не через ручные проверки
  `window.innerWidth`.

### ScrollTrigger
- Не создавай ScrollTrigger на каждый элемент списка, если хватает одного на контейнер
  с `stagger`.
- После загрузки картинок, шрифтов или динамической подгрузки контента вызывай
  `ScrollTrigger.refresh()`.
- `markers: true` — только на время отладки, в коммит попадать не должно.
- WordPress добавляет к картинкам `loading="lazy"`, из-за чего высота страницы меняется
  на лету и триггеры съезжают. Задавай контейнерам картинок `aspect-ratio` и вешай
  `ScrollTrigger.refresh()` на `window.load`.
- У залогиненного пользователя сверху висит админ-бар (32px, на мобильных 46px и
  `position: fixed`). Не завязывай позиционирование фиксированной шапки на `top: 0`
  жёстко — используй переменную, которую можно переопределить.

### Доступность
Обязательно уважай `prefers-reduced-motion`:

```js
const mm = gsap.matchMedia();

mm.add('(prefers-reduced-motion: no-preference)', () => {
  // анимации
});
```

Контент должен быть виден и читаем, даже если анимации не отработали. Не прячь текст
через `opacity: 0` в CSS без гарантии, что JS его покажет.

### Мера
Одна выразительная анимация лучше, чем fade-up на каждой секции и hover-эффект
на каждой карточке. Движение по действию пользователя (открытие, раскрытие,
подтверждение) — приветствуется. Автоматическое движение — только там, где оно
действительно направляет внимание.

## Vite

- Не собирай пути конкатенацией строк в JS: сборщик такое не увидит, а после натяжки
  на тему путь сменится. См. правила по путям в разделе «WordPress».
- Каждая страница вёрстки — отдельный html в корне, все они перечислены в
  `build.rollupOptions.input` в `vite.config.js`. Одна страница вёрстки соответствует
  одному будущему шаблону темы.
- Хеши в именах файлов сборки можно отключить (`build.rollupOptions.output.entryFileNames`),
  чтобы пути в `functions.php` не приходилось менять после каждой пересборки.
- Секреты и ключи в клиентский код не попадают. Переменные с префиксом `VITE_`
  публичны по определению.

## WordPress

Мы не пишем PHP в этом репозитории — только вёрстку. Но она должна разбираться
на шаблоны без переписывания. Правила ниже про это.

### Разбивка на шаблоны
Держи в голове, куда уедет каждый кусок разметки:

| HTML | Шаблон темы |
|---|---|
| всё до `<main>` | `header.php` |
| всё после `<main>` | `footer.php` |
| главная | `front-page.php` |
| обычная страница | `page.php` |
| статья | `single.php` |
| листинг блога | `index.php` / `archive.php` |
| повторяемый блок (карточка, слайд) | `template-parts/*.php` |

Практический вывод: шапка и подвал должны быть **побайтово одинаковыми** на всех
страницах. Если на главной шапка прозрачная, а на внутренней белая — это модификатор
класса на одном и том же блоке, а не вторая вёрстка шапки.

### Повторяемые элементы
Карточка, пункт списка, слайд, элемент меню — это будущий `while (have_posts())`.
Поэтому:
- Разметка всех однотипных элементов идентична до атрибута. Никаких «у второй карточки
  чуть другая структура».
- Никаких стилей через `:nth-child()` для оформления — количество элементов задаётся
  в админке и меняется. Исключение: чередование фона `:nth-child(even)`, если оно
  работает при любом числе элементов.
- Уникальные `id` — только там, где элемент гарантированно один на странице. Для
  повторяемых блоков используй классы и `data-*`.
- Верстай минимум 3 элемента в списке, чтобы было видно поведение сетки, но проверяй,
  что вёрстка не разваливается при 1 и при 7.

### Секции и ACF
Контент выводится через ACF: секции страниц собираются в Flexible Content, повторяемые
элементы внутри них — Repeater. Порядок секций и их количество задаёт редактор в админке.

- **Каждая секция самодостаточна.** Она не знает, что было до неё и что будет после.
  Вертикальные отступы живут на самой секции (`padding`, а не `margin`, чтобы не
  схлопывались), фон задан явно. Секция должна выглядеть нормально и первой на странице,
  и последней, и рядом с такой же.
- Не стилизуй секции через `+`, `~` и `:first-child` — соседи меняются.
- Чередование фонов задаётся модификатором класса (`.section--light` / `.section--dark`),
  который редактор выбирает полем в админке. Никаких `:nth-child(even)` на секциях.
- Давай каждой секции `data-section="hero"` со стабильным именем — по нему секция
  сопоставляется с layout'ом во Flexible Content.
- Одна секция — один файл в `src/styles/sections/` и, если нужна логика, один файл
  в `src/scripts/`. Модуль инициализируется по всем найденным экземплярам секции
  (`querySelectorAll`), потому что одна и та же секция может встретиться на странице дважды.

### Необязательные поля
Почти любое поле редактор может оставить пустым, и тогда элемент просто не выведется.
Вёрстка не должна от этого разваливаться:
- Подзаголовок, кнопка, картинка, описание — верстай так, чтобы при удалении элемента
  не оставалось пустых отступов. Отступы задавай через `gap` у контейнера или через
  `margin-top` у следующего элемента, а не `margin-bottom` у предыдущего.
- Разделители, точки, палочки между мета-данными — не `content` в псевдоэлементах
  подряд, иначе при одном элементе останется висящий разделитель. Используй `gap`
  и границы, либо `:not(:last-child)`.
- Сделай версии секции: с картинкой и без, с кнопкой и без. Достаточно закомментировать
  блок в HTML и убедиться, что макет держится.

### Типовые поля и что от них ждать
- **Link** возвращает url, текст и target. Кнопка должна переживать текст в 1 слово и
  в 5, и `target="_blank"`.
- **Image** возвращает массив с размерами и `alt`. Обёртке — `aspect-ratio`, картинке —
  `object-fit: cover`. Пропорции задаёт вёрстка, не файл.
- **WYSIWYG** — тот самый поток тегов без классов, оборачивай в `.content`.
- **Repeater** — верстай минимум 3 элемента, проверяй на 1 и на 7.
- **Gallery** — количество произвольное, сетка должна тянуться.
- Контакты, соцсети, логотип в шапке и подвале приходят с Options-страницы: они
  одинаковы на всём сайте, но редактируемы. Не считай их константами вёрстки.

### Контент из админки
- Любой текст можно будет отредактировать. Не зашивай текст в `content` псевдоэлементов
  и не рисуй его картинкой — только реальные текстовые узлы.
- Длина текста будет другой. Заголовок из 2 слов и из 15 должны выглядеть нормально:
  никаких фиксированных высот у блоков с текстом, обрезка — через `line-clamp`.
- Блок текста из редактора (`the_content()`) приходит как поток `<p>`, `<h2>`, `<ul>`,
  `<blockquote>`, `<table>`, `<figure>` без классов. Заведи под это класс-обёртку
  (`.content`) со стилями по тегам — это единственное место, где допустимы селекторы
  по тегам.
- Картинки WordPress отдаёт со своими `srcset`, `sizes`, `width`, `height` и часто
  внутри `<figure class="wp-block-image">`. Не завязывай стили на конкретную обёртку:
  задавай размер контейнеру, а `img` — `width: 100%; height: 100%; object-fit: cover`.

### Меню
`wp_nav_menu()` выдаёт жёсткую структуру, повторяй её в вёрстке:

```html
<ul class="menu">
  <li class="menu-item menu-item-has-children current-menu-item">
    <a href="#">Пункт</a>
    <ul class="sub-menu">
      <li class="menu-item"><a href="#">Подпункт</a></li>
    </ul>
  </li>
</ul>
```

Активный пункт стилизуй через `.current-menu-item`, а не через отдельный класс.
Стрелку у пункта с подменю вешай на `.menu-item-has-children`, а не на конкретный `li`.

### Формы
Формы будут заменены на Contact Form 7 или аналог, который генерирует разметку сам.
Верстай их так, чтобы стили держались на структуре `label > input`, а не на цепочках
классов. Кнопке отправки давай класс, который потом задаётся в настройках формы.
Состояния ошибки и успеха тоже сверстай — плагин их выводит.

### Пути к ассетам
В теме относительные пути от CSS-файла продолжат работать, а абсолютные — нет:
на проде тема лежит в `/wp-content/themes/название/`.
- В CSS — только относительные пути (`url('../assets/img/bg.jpg')`).
- В HTML — пути от корня, они всё равно будут заменены на
  `<?php echo get_template_directory_uri(); ?>/...` при натяжке. Собирай их в атрибутах
  тегов, а не в JS.
- Шрифты и декоративная графика — в `src/assets/`. Контентные картинки в вёрстке —
  заглушки, они уедут в медиабиблиотеку.

### Классы и id, которые занимает WordPress
Не используй в своей вёрстке имена, которые WP выдаёт сам: `.alignleft`, `.alignright`,
`.aligncenter`, `.wp-*`, `.screen-reader-text`, `.sticky`, `.gallery`, `#wpadminbar`.
`body_class()` и `post_class()` добавляют классы к `<body>` и к элементам записей —
свои классы на них тоже вешай, но не рассчитывай, что список ограничится ими.

## Чего не делать

- Не добавляй зависимости без спроса — сначала предложи и объясни зачем.
- Не переписывай существующие файлы целиком, если нужно поменять одну функцию.
- Не создавай README, документацию и комментарии «на будущее», если не просили.
- Не оставляй `console.log` в коде.
- Не меняй структуру папок по своему усмотрению.
